# 模块一 · 🛒 Go 商城系统（课时 1–109，18 章）

> 这是整套系统的底座，已在 qingfly.com 生产商用。
> 后端 `edu.mall.backend`（Go+Gin+GORM），C 端前端 `edu.mall.customer`，管理后台 `edu.mall.frontend`（React + Ant Design Pro）。
> 学习节奏：**先方案、后框架、再逐功能开发、最后部署上线**——这也是老师贯穿全课的通用方法论。

## 1.1 项目基础准备（7 节）
打地基阶段，统一团队的技术语言和工程习惯。
- **产品需求分析 / 技术文档框架**：先写 PRD 和技术文档骨架，再动手写代码。
- **MySQL 介绍和简单使用**：建库建表、索引、事务基础。
- **git 协作流程简单使用**：分支策略、Code Review 习惯。
- **服务配置和环境变量**：配置分层（默认值 → env 覆盖），敏感信息不进代码库。
- **gorm 和 gentool 的使用**：用 GORM 做 ORM，用 gentool 从表结构自动生成 model。
- **ApiFox 使用和接口管理**：接口先行，前后端并行开发。

## 1.2 技术方案设计（7 节）
- **技术架构设计 / 模块设计**：分层架构（router → api/handler → service → dao），职责单一。
- **数据库结构设计**：课程、订单、用户、RBAC 等核心表的 ER 设计与字段取舍。
- **接口设计**：RESTful 规范、统一响应结构 `{code, msg, data}`。
- **后端服务框架 / 技术方案评审 / 项目管理和项目计划**：搭好脚手架并做评审排期。

## 1.3 后端服务框架开发（9 节）
把空架子变成能跑的服务骨架（分六段递进）：
- **代码框架一~六**：目录结构、启动入口、依赖注入、路由注册、优雅退出。
- **日志中间件（两节）**：请求日志、traceId 透传、结构化日志。
- **鉴权中间件**：token 解析、登录态校验、上下文注入用户信息。

## 1.4 管理后台登录（14 节）
后台是运营侧入口，登录做得最重：
- **api 接口全流程 / 滑块校验（三节）**：人机验证防刷。
- **手机号登录（三节）**：密码登录主链路。
- **手机号验证码登录（四节，含飞书扫码/飞书验证码）**：多通道验证码下发与校验。
- **多种登录方式-菜单可配置**：登录方式做成可配置项而非写死。
- **飞书扫码绑定和解绑 / 登出系统和重置密码**。

## 1.5 管理员角色权限 RBAC（6 节）
- **管理员管理 / 菜单权限配置（二节）**：动态菜单 + 按钮级权限。
- **角色管理（二节）/ 给角色分配权限**：标准 RBAC（用户—角色—权限—资源）。

## 1.6 录播管理（12 节）
课程内容本身的管理（元数据管理）：
- **录播目录管理（二节）**：多级目录树增删改查。
- **腾讯云对象存储（COS）讲解 / 骨架代码 / 实现（三节）**：视频文件上传到 COS，数据库只存 key。
- **完成录播课时创建 / 列表（二节）/ 编辑（二节）**。
- **录播课时 bug 修复 / 视频更新清理**：真实踩坑与清理旧版本。

## 1.7 课程管理（8 节）
- **课程基本信息 / 更新和列表 / 详情和列表微调**。
- **课程目录管理（四节）**：把录播课时组织成对外售卖的课程目录。
- **整体部署运行**：本模块阶段性上线验证。

## 1.8 用户注册登录 C 端（6 节）

- **滑块和验证码 / 手机验证码登录 / 密码登录和用户信息接口**。
- **登录即注册 & 手机号加密存储**：手机号 AES 加密落库（呼应全站加密习惯）。

## 1.9 课程商品列表（5 节）
- **C 端商品列表 / 详情 / 课时详情 / 已购买课程（二节）**：商品展示 + 购买态判断。

## 1.11 用户购物车（2 节）
加购、改数量、结算前校验库存与价格。

## 1.12 管理后台用户管理（1 节）
运营侧查看/管理注册用户。

# 模块二 · 🔌 WebSocket 高并发连接层（课时 110–141，3 章）

> 独立仓库 `edu.mall.websocket`。职责单一：**只做消息推送和在线状态管理，不碰任何业务逻辑**。
> 对外提供三个 gRPC 接口：`WebSocketSend`、`IsOnlineUsers`、`GetOnlineCount`。
> 技术选型：**OpenResty + Nchan**（Nginx 层扛长连接）+ **go-zero zrpc**（Go 服务层）+ **Redis Pub/Sub**（跨进程广播）。
> 目标指标：单机四万连接压测通过、分布式多节点故障自愈。

## 2.1 课程介绍和入门（10 节）
- **websocket 课程介绍和大纲 / 课件准备**。
- **websocket 是什么，解决什么问题**：HTTP 短连接的痛点 → 全双工长连接。
- **站内信 & 消息系统的业务模型拆解**：先想清楚"谁推给谁、什么时机"。
- **WebSocket 服务的三种实现方案对比**：纯 Go / Nginx+后端 / OpenResty+Nchan，最终选 Nchan 方案。
- **OpenResty 是什么？为什么不用普通 Nginx**：Lua 扩展能力。
- **Nchan 核心概念入门**：channel、sub/unsub、streaming。
- **编译安装 OpenResty + Nchan / 第一个 Nchan WebSocket Demo / 高级配置与真实项目用法**。

## 2.2 技术方案和架构（6 节）
- **高并发 Websocket 消息推送系统技术方案**：整体架构图、数据流、扩缩容策略。
- **Golang 服务工程结构开发**（分 grpc / http / 代码结构 / 配置 四节）：统一 go-zero 工程骨架。

## 2.3 发布订阅 Session 管理（7 节）★核心难点
- **sub/unsub 的内存 Session 管理（二节）**：单进程内连接表。
- **sub/unsub 的全局 Session 管理（三节）**：多进程/多节点共享的在线状态（Redis）。
- **节点心跳和故障自动清理（二节）**：节点挂了自动摘除其名下连接，避免僵尸 session。

## 2.4 消息推送与性能测试（9 节）
- **gRPC 消息发送接口 / http 消息发送接口**：两种接入方式。
- **Redis 发布订阅在系统中的真实用途**：A 进程收到消息→Pub→所有节点 Sub→各自推给本地持有的连接。
- **nchan 发送 websocket 消息封装**：把推送逻辑收敛到一个函数。
- **前端 WebSocket 联调与异常场景**：断线重连、心跳保活、鉴权握手。
- **全链路性能测试与瓶颈分析 / 单机四万连接测试 / 分布式多节点故障自愈**。
- **补充：连接经过 auth 鉴权处理**：握手阶段校验 token。

# 模块四 · 🤖 AI Agent 智能体系统（课时 197–301，8 章）

> 独立仓库 `edu.agent.code`。基于字节跳动 **eino** 框架构建的 Go 原生 Agent 服务。
> 核心理念：**模型、工具、MCP 服务全部抽象为"原子能力"，在管理后台自由组合成 Agent，改完即时生效，不用发版。**
> 支持多轮对话、工具调用、SSE 流式输出、RAG 知识库、人机协作中断恢复。
> 数据库用 SQLite（轻量），链路追踪 OpenTelemetry，前端 VibeCoding 对接。

# 模块五 · 🔗 微服务融合实战直播（课时 302–317，16 节）

> 前面四套系统各自独立。这 16 节课（10 次直播主题 + 演示/方案）把它们用**微服务架构打通并上线 qingfly.com**。
> 命名风格：`演示：…` / `直播第 N 节：微服务集成 XX 改造 M（k）`——一个改造点拆成多段直播连续推进。

## 5.0 成果演示（2 节）
- **演示：微服务集成智能体 IM 系统一 / 二**：先看最终效果，建立目标感。

## 5.1 直播第一节 · 微服务集成技术方案（三节）
整体融合方案设计：服务边界、gRPC 拓扑、Etcd 注册发现、数据一致性策略。

## 5.2 直播第二节 · 统一 gRPC & 统一鉴权（二节）★关键改造
- IM 和 Agent **不再自己签发 token**，全部透传给商城 backend 做统一验证。
- **一次登录，全系统通行；踢人、吊销只有一个入口。**

## 5.3 直播第三节 · 集成 IM 系统改造（三节）
- **IM 用户体系改造**：不再自存 nickname/avatar 副本，所有用户资料由 Backend 统一管理，IM 和 Agent 通过 gRPC 实时获取。

## 5.4 直播第四节 · 集成 IM 系统改造四（三段）
- **群机器人 @ 触发 Agent**：群里加机器人→绑定一个 Agent→@ 它就触发推理。
- 回复经 WebSocket 逐字推送到群里，所有人都能看到"它在思考"的过程。

## 5.5 直播第五节 · 集成 IM 系统改造五（三段）
- **Agent 可配置化收尾**：模型、工具、MCP 在管理后台自由增删，运营自助完成，无需发版。
- **前端融合**：IM 聊天、Agent 对话、课程浏览整合到一个用户端，顶部导航五个入口——首页、课程、智能体、消息、我的。
- **Docker Compose 部署 + CICD**：每个服务独立 Docker Compose、独立 CNB 流水线，打 tag 自动构建镜像→推服务器→拉起容器。

# 附一 · 老师的代码风格与工程方法论（从课时命名/结构反推）

这套课的"味道"非常一致，写代码时对齐这些习惯即可高度还原老师风格：

1. **先文档后代码**：每个子系统都从「产品需求分析 → 技术文档框架 → 技术方案评审」开始，评审常分一/二/三轮逐步收敛。
2. **分层严格**：`router(路由) → api/handler → service → dao/model`，中间件（日志/鉴权）横切，职责单一不越层。
3. **配置分层 + 环境变量覆盖**，敏感信息（密钥、手机号）加密或走 env，不落明文进库/进仓。
4. **接口先行 + 统一响应** `{code, msg, data}`，配合 ApiFox 管理，前后端并行。
5. **model 用 gentool/GORM 从表生成**，不手抄字段。
6. **拆段递进**：复杂功能一定拆「一/二/三…」多节，每节一个可运行增量；先跑通骨架再填 TODO（IM 里大量 `TODO处理` 课即是）。
7. **真实踩坑即内容**：`bug修复`、`实战修复`、`联调收尾优化`、`加餐` 是常态，不藏问题。
8. **AI 辅助编码是标配**：AICoding / VibeCoding 反复出现，但强调 AI 出初版、人来 review 迭代。
9. **可观测性内建**：traceId 透传、结构化日志、OpenTelemetry 链路追踪、Callback 观测 Agent 执行。
10. **幂等与状态机**：支付回调、退款、订单超时都按异步回调 + 状态机 + 幂等设计。
11. **项目命名规范**：`edu.mall.backend / customer / frontend / websocket / webchat / webchatui`、`edu.agent.code`——业务域前缀 + 端/角色后缀。
