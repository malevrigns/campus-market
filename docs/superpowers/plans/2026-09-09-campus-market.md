# 校园集市实施与验收

**目标**：保留校园二手交易业务，贯通真实持久化 API、后端支付、即时消息、Agent 与移动界面。

**架构选择**：现有四个入口只有内存示例与占位 adapter，直接分布式扩展会放大数据一致性问题。增加 `cmd/server` 作为可部署的模块化后端，模块共享 SQLite WAL 事务与统一会话；旧教学内核保留作参考，旧入口不进入部署。相比只改前端，它能验证真实闭环；相比立即引入 MySQL/Redis/Etcd/Milvus，单节点方案可直接在当前环境运行并做故障测试。多节点部署和课程中全部管理能力单独列为尚未交付的范围。

**全局约束**：金额使用整数分；用户身份来自 HttpOnly 会话；客户端不得决定金额、卖家、支付成功或工具权限；未配置支付/模型不可伪造成功；移动端安全区、键盘和减少动态效果必须适配。禁止提交密钥或数据库。

## 1. 后端持久化与身份

- [x] `backend/internal/platform/{store,server,auth,catalog}.go`：SQL schema/version、事务、bcrypt 密码、会话吊销、同源保护、限流、严格 JSON、商品与收藏。
- [x] `backend/internal/platform/platform_test.go`：HTTP 注册登录、越权、重启持久化和非法请求。
- [x] `backend/cmd/server/main.go`：参数检查、数据库生命周期、超时、优雅关闭。

## 2. 服务端订单与支付

- [x] `orders.go`：服务端计价快照、库存原子预占、按用户隔离幂等键、取消释放、卖家面交/买家确认、退款申请记录。
- [x] `payments.go`：后端生成支付宝支付 URL；RSA2 验签、商户和金额核对、回调与交易号持久去重。未配置返回 503，前端只展示支付入口和查询订单。
- [x] 验收恶意价格字段、跨用户查询、并发抢同一商品、重复回调、错误金额、取消与支付竞态。

## 3. IM 与 Agent

- [x] `chat.go`：持久会话、成员校验、消息 seq、按发送者去重、游标同步、已读水位、WebSocket 事件与重连补拉。
- [x] `agent.go`：持久对话/run、SSE、取消、模型超时、后端只读商品/本人订单工具、无模型明确不可用。
- [x] 验收非成员访问、断线同步、重复消息、跨用户 run、SSE 格式与失败终态。
