# 身份验证修复与体验改造

用户反馈注册/登录失败，并明确要求邮箱、手机验证码、明暗主题和可移动的页面内 AI 助手。保留现有数据与动态 Agent 管理台。

已复现：同一主机不同端口的两套后端使用相同 Cookie 名，第二次登录覆盖第一次会话，回到第一套环境 `/auth/me` 返回 401。验证码注册、短信登录和找回密码确实尚未提供，不能用现有密码登录的 E2E 通过替代这些功能的验收。

- [x] 按开发站点隔离 Cookie，生产使用 Secure/HttpOnly 的 host Cookie；旧会话兼容读取。错误密码不能广播成全局会话过期。
- [x] 验证码：邮箱/短信、注册/登录/重设密码/验证绑定用途隔离；6 位随机码、HMAC 存储、5 分钟期限、单次消费、5 次尝试、重发冷却及发送配额；网络发送在事务外，失败如实返回。
- [x] 身份表兼容旧邮箱账号；新注册先验证邮箱或手机号。密码登录、验证码登录、忘记密码、补充验证或绑定身份均有对应前后端流程。
- [x] 发送层：SMTP TLS 邮件、阿里云短信适配；本地模式只在开发环境开放受随机能力令牌保护的测试收件箱，生产禁止。无服务凭据时明确禁用，不伪造实发。
- [x] 登录面板提供输入校验、验证码发送/重发/倒计时、错误提示、密码显隐及开发收件箱；不依赖浏览器隐藏的原生表单气泡解释失败。
- [x] 明暗主题切换并持久化；浮动 AI 图标可拖动、受视口约束、保留位置；当前页面内展开对话、支持手机；顾客入口不再跳转独立 AI 页，管理台保持独立。
- [x] Go 与浏览器回归：跨端口会话、验证码错误/过期/重放/用途错配、密码重置后撤销会话、主题刷新、拖动后不误点击、移动端弹层；启动最新体验环境并给出唯一清楚的入口。

服务商选择是可选补充信息：用户未提供真实 SMTP/短信凭据时，先用明确标识的本地收件箱做闭环验收；代码中的真实适配与实际短信/邮件送达验收分开记录。
